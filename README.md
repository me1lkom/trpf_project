# Сервис сравнения предложений поставщиков

## Назначение

Приложение для автоматизации выбора наиболее выгодных предложений от поставщиков.

Сервис позволяет работать с товарами, поставщиками и их предложениями, сравнивать условия поставок по различным параметрам: цене, минимальной партии и сроку доставки.

## Целевая аудитория

- Менеджеры по закупкам.
- Владельцы малого бизнеса, самостоятельно занимающиеся закупками.

## Предметная область

Сервис предназначен для анализа предложений на один и тот же товар с учётом цены, объёма заказа, минимальной партии и срока доставки.

Основные сущности:

- **Пользователь (User)** — пользователь системы.
- **Товар (Product)** — товар, для которого рассматриваются предложения.
- **Поставщик (Supplier)** — организация, предлагающая товары.
- **Предложение (Offer)** — условия поставки определённого товара конкретным поставщиком.

## Основные классы

### Product — товар

Объект `Product` представляет товар, на который ищутся предложения.

**Атрибуты:**
- `id` — идентификатор товара;
- `name` — название;
- `description` — описание;
- `country` — страна производства.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `from_data()` — создание объекта из словаря JSON.

### Supplier — поставщик

Объект `Supplier` представляет поставщика, предлагающего товары.

**Атрибуты:**
- `id` — идентификатор поставщика;
- `name` — название;
- `inn` — ИНН;
- `phone` — телефон;
- `email` — email.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `from_data()` — создание объекта из словаря JSON.

### Offer — предложение

Объект `Offer` связывает товар и поставщика с условиями предложения.

**Атрибуты:**
- `id` — идентификатор предложения;
- `product` — объект `Product`;
- `supplier` — объект `Supplier`;
- `price` — цена;
- `min_lots` — минимальная партия;
- `delivery_time_days` — срок доставки в днях.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `check_min_lot(quantity)` — проверка минимальной партии;
- `calculate_order_price(quantity)` — расчёт стоимости заказа.

### User — пользователь

Объект `User` представляет пользователя системы.

**Атрибуты:**
- `id` — идентификатор пользователя;
- `name` — имя;
- `email` — email.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `from_data()` — создание объекта из словаря JSON.

## Основные функции

### Пользователи
- просмотр списка пользователей;
- добавление пользователя;
- поиск пользователя по имени;
- поиск пользователя по ID.

### Товары
- просмотр списка товаров;
- добавление товара;
- поиск товара по названию;
- поиск товара по ID.

### Поставщики
- просмотр списка поставщиков;
- добавление поставщика;
- поиск поставщика по названию;
- поиск поставщика по ID.

### Предложения
- просмотр списка предложений;
- добавление предложения;
- поиск предложений по товару;
- фильтр предложений по максимальной цене;
- фильтр предложений по максимальному сроку доставки;
- сортировка предложений по цене;
- поиск лучшего предложения по цене;
- проверка минимальной партии;
- расчёт стоимости заказа.

## Веб-интерфейс

Веб-интерфейс позволяет:
- Просматривать списки товаров, поставщиков и предложений.
- Открывать страницы с подробной информацией об объектах.
- Переходить между разделами через навигационные ссылки.
- Просматривать сведения о товаре и поставщике, связанных с предложением.
- Получать страницу с ошибкой HTTP 404 при обращении к несуществующим объектам или адресам.

### Django-приложения

- `homepage` — главная страница и общий обработчик ошибки 404.
- `products` — список товаров и страницы отдельных товаров.
- `suppliers` — список поставщиков и страницы отдельных поставщиков.
- `offers` — список предложений и страницы отдельных предложений.

### Основные URL

| URL | Назначение |
|---|---|
| `/` | Главная страница |
| `/products/` | Список товаров |
| `/products/<int:product_id>/` | Информация о товаре |
| `/suppliers/` | Список поставщиков |
| `/suppliers/<int:supplier_id>/` | Информация о поставщике |
| `/offers/` | Список предложений |
| `/offers/<int:offer_id>/` | Информация о предложении |

Для маршрутизации используются файлы `urls.py`. Обработка HTTP-запросов выполняется view-функциями, расположенными в `views.py` соответствующих приложений.


Для формирования HTML-страниц используется Django Template Language (DTL). Общая структура интерфейса определена в базовом шаблоне `base.html`, от которого наследуются шаблоны отдельных страниц с помощью `{% extends %}` и `{% block %}`.

Повторяющиеся элементы интерфейса вынесены в подключаемые шаблоны с использованием `{% include %}`. Данные передаются из view-функций в шаблоны через словарь `context`, а для их отображения используются циклы `{% for %}`, условия `{% if %}` и фильтры `length` и `default`.

Для формирования ссылок используются именованные маршруты и пространства имён приложений (`app_name`) с тегом `{% url %}`.

Интерфейс оформлен с использованием Bootstrap 5.3 и собственных CSS-стилей. Статические файлы подключаются средствами Django через `{% load static %}` и `{% static %}`. В проекте используются собственный CSS, JavaScript для отображения текущего года и изображение логотипа.

При обращении к несуществующему идентификатору соответствующая view-функция возвращает HTTP 404. Для несуществующих URL настроен общий обработчик `handler404`.

### Использование логики ПР3

Веб-интерфейс использует существующие классы и функции предметной области:

- `load_products()` — загрузка товаров;
- `load_suppliers()` — загрузка поставщиков;
- `load_offers()` — загрузка предложений;
- `get_product_by_id()` — поиск товара;
- `get_supplier_by_id()` — поиск поставщика;
- `get_offer_by_id()` — поиск предложения.

При загрузке предложений идентификаторы товаров и поставщиков преобразуются в ссылки на соответствующие объекты `Product` и `Supplier`.

Данные предметной области продолжают храниться в JSON-файлах. Переход на Django ORM для этих сущностей на данном этапе не выполняется.

Консольная версия приложения сохранена и может использоваться независимо от веб-интерфейса.

## Формат хранения данных

Данные предметной области хранятся в JSON-файлах каталога `data/`:

- `products.json` — список товаров;
- `suppliers.json` — список поставщиков;
- `offers.json` — список предложений;
- `users.json` — список пользователей.

Функции загрузки и сохранения данных находятся в модуле `storage.py`.

Для служебных компонентов Django используется SQLite. Файл `db.sqlite3` создаётся после применения миграций. Данные товаров, поставщиков и предложений в этой базе пока не хранятся.

## Требования

- Python 3.10+;
- Django 5.2;
- pytest;
- flake8.

## Установка зависимостей

Из корневого каталога проекта создайте виртуальное окружение:

```bash
python3 -m venv venv
```

Активируйте его (macOS/Linux):

```bash
source venv/bin/activate
```

Установите зависимости:

```bash
python3 -m pip install -r requirements.txt
```

## Запуск консольной версии

Из корневого каталога проекта выполните:

```bash
python3 main.py
```

Консольная версия предоставляет меню для работы с данными предметной области.

## Запуск веб-версии

Перед первым запуском примените встроенные миграции Django:

```bash
python3 manage.py migrate
```

Проверьте конфигурацию:

```bash
python3 manage.py check
```

Запустите сервер разработки:

```bash
python3 manage.py runserver
```

После запуска веб-интерфейс будет доступен по адресу:

http://127.0.0.1:8000/

Для остановки сервера нажмите `Ctrl+C` в терминале.

## Тестирование

Для запуска автоматизированных тестов:

```bash
python3 -m pytest -v
```

Тесты проверяют функции и методы предметной области, реализованные в консольной версии приложения.

Для проверки конфигурации Django:

```bash
python3 manage.py check
```

Для проверки стиля Python-кода:

```bash
python3 -m flake8 .
```

Работу веб-интерфейса дополнительно можно проверить в браузере: открытие главной страницы, списков объектов, динамических URL и обработку несуществующих идентификаторов.
