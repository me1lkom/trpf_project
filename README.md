# Сервис сравнения предложений поставщиков

## Назначение

Приложение для автоматизации выбора наиболее выгодных предложений от поставщиков.

Сервис позволяет работать с товарами, поставщиками и их предложениями, сравнивать условия поставок по различным параметрам: цене, минимальной партии и сроку доставки.

## Целевая аудитория

- Менеджеры по закупкам.
- Владельцы малого бизнеса, самостоятельно занимающиеся закупками.

## Предметная область

Сервис предназначен для анализа предложений на один и тот же товар с учётом цены, объёма заказа, минимальной партии и срока доставки.

Основные сущности:

- **Пользователь (`User`)** — физическое лицо, использующее систему.
- **Товар (`Product`)** — запрос на товар с определёнными характеристиками, для которого рассматриваются предложения.
- **Поставщик (`Supplier`)** — организация, предлагающая товары. Организация также может выступать заказчиком.
- **Предложение (`Offer`)** — условия поставки конкретного товара определённым поставщиком.

## Основные классы

### Product — товар

Объект `Product` представляет товар, на который ищутся предложения.

**Атрибуты:**
- `id` — идентификатор товара;
- `name` — название;
- `description` — описание;
- `country` — страна производства.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `from_data()` — создание объекта из словаря JSON.

### Supplier — поставщик

Объект `Supplier` представляет поставщика, предлагающего товары.

**Атрибуты:**
- `id` — идентификатор поставщика;
- `name` — название;
- `inn` — ИНН;
- `phone` — телефон;
- `email` — email.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `from_data()` — создание объекта из словаря JSON.

### Offer — предложение

Объект `Offer` связывает товар и поставщика с условиями предложения.

**Атрибуты:**
- `id` — идентификатор предложения;
- `product` — объект `Product`;
- `supplier` — объект `Supplier`;
- `price` — цена;
- `min_lots` — минимальная партия;
- `delivery_time_days` — срок доставки в днях.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `check_min_lot(quantity)` — проверка минимальной партии;
- `calculate_order_price(quantity)` — расчёт стоимости заказа.

### User — пользователь

Объект `User` представляет пользователя системы.

**Атрибуты:**
- `id` — идентификатор пользователя;
- `name` — имя;
- `email` — email.

**Методы:**
- `__init__()` — создание объекта;
- `__str__()` — строковое представление;
- `from_data()` — создание объекта из словаря JSON.

## Основные функции

### Пользователи

- Просмотр списка пользователей.
- Добавление пользователя.
- Поиск пользователя по имени и ID.

### Товары

- Просмотр списка товаров.
- Добавление товара.
- Поиск товара по названию и ID.

### Поставщики

- Просмотр списка поставщиков.
- Добавление поставщика.
- Поиск поставщика по названию и ID.

### Предложения

- Просмотр списка предложений и добавление предложения.
- Поиск предложений по товару.
- Фильтрация по максимальной цене и сроку доставки.
- Сортировка предложений по цене и поиск лучшего предложения по цене.
- Проверка минимальной партии и расчёт стоимости заказа.

## Веб-интерфейс

Веб-версия создана на Django и получает данные предметной области из SQLite с помощью SQL-запросов.

Реализованы:

- Просмотр списков товаров, поставщиков и предложений.
- Страницы с подробной информацией о каждом объекте.
- Отображение заказчика товара: физического лица или организации.
- Просмотр предложений для выбранного товара и их сортировка по цене или сроку доставки с помощью GET-параметра `sort`.
- Статистика цен для товара: минимальная, максимальная и средняя цена, количество предложений.
- Просмотр предложений конкретного поставщика вместе с товарами и заказчиками.
- Общий реестр предложений и отдельная страница каждого предложения.
- Страница статистики сервиса с общими показателями и количеством предложений по товарам и поставщикам.
- Навигация между разделами и обработка HTTP 404 для несуществующих объектов и URL.

### Django-приложения

- `homepage` — главная страница, статистика сервиса и общий обработчик ошибки 404.
- `products` — список товаров и страницы отдельных товаров с предложениями.
- `suppliers` — список поставщиков и страницы отдельных поставщиков с предложениями.
- `offers` — общий список предложений и подробные страницы предложений.

### Основные URL

| URL | Назначение |
|---|---|
| `/` | Главная страница |
| `/products/` | Список товаров |
| `/products/<int:product_id>/` | Информация о товаре, заказчике и предложениях |
| `/suppliers/` | Список поставщиков |
| `/suppliers/<int:supplier_id>/` | Информация о поставщике и его предложениях |
| `/offers/` | Общий список предложений |
| `/offers/<int:offer_id>/` | Подробная информация о предложении |
| `/statistics/` | Общая статистика сервиса |

Для маршрутизации используются файлы `urls.py`, а обработка HTTP-запросов выполняется функциями в `views.py` соответствующих приложений. Ссылки формируются по именованным URL через тег `{% url %}` и пространства имён `app_name`.

Для HTML-страниц используется Django Template Language (DTL). Общая структура интерфейса задана в `base.html`; страницы наследуются с помощью `{% extends %}` и `{% block %}`, а повторяющиеся элементы подключаются через `{% include %}`. Данные передаются в шаблоны через `context`; применяются `{% for %}`, `{% if %}`, фильтры `length` и `default`.

Интерфейс оформлен с использованием Bootstrap 5.3 и собственных CSS-стилей. Статические файлы подключаются с помощью `{% load static %}` и `{% static %}`. В проекте также используются логотип и JavaScript для отображения текущего года.

При обращении к несуществующему идентификатору view-функция возвращает HTTP 404. Для несуществующих URL настроен общий обработчик `handler404`.

### Использование логики предыдущих практических работ

Классы `Product`, `Supplier`, `Offer`, `User` и функции работы с JSON сохранены для консольной версии приложения. Консольная программа продолжает работать независимо от Django.

Начиная с ПР7, Django-представления получают данные непосредственно из `data/trpf.sqlite` через стандартный модуль Python `sqlite3`. Результаты запросов возвращаются в виде `sqlite3.Row` и передаются в HTML-шаблоны через `context`.

JSON-файлы остаются исходными данными для импорта в SQLite и работы консольной версии. Django ORM для сущностей предметной области пока не используется.

## База данных SQLite (ПР7)

Для хранения данных предметной области создана база **`data/trpf.sqlite`**. Её структура определена в файле **`sql/schema.sql`**.

### Таблицы и поля

| Таблица | Поля и типы | Ключи и ограничения |
|---|---|---|
| `users` | `user_id INTEGER`, `name TEXT`, `email TEXT` | PK: `user_id`; `email UNIQUE` |
| `suppliers` | `supplier_id INTEGER`, `name TEXT`, `inn TEXT`, `phone TEXT`, `email TEXT` | PK: `supplier_id`; `inn UNIQUE` |
| `products` | `product_id INTEGER`, `name TEXT`, `description TEXT`, `country TEXT` | PK: `product_id` |
| `offers` | `offer_id INTEGER`, `product_id INTEGER`, `supplier_id INTEGER`, `price REAL`, `min_lots REAL`, `delivery_time_days INTEGER` | PK: `offer_id`; FK: `product_id`, `supplier_id` |
| `supplier_members` | `user_id INTEGER`, `supplier_id INTEGER` | Составной PK: (`user_id`, `supplier_id`); оба поля — FK |
| `product_buyers` | `product_id INTEGER`, `user_id INTEGER`, `supplier_id INTEGER` | PK: `product_id`; все три поля — FK; проверка типа заказчика (`CHECK`) |

В таблицах определены ограничения `NOT NULL` для обязательных полей. Таблица `product_buyers` допускает ровно одного заказчика для каждого товара: либо пользователя (`user_id`), либо организацию (`supplier_id`). Это обеспечивается ограничением `CHECK`.

### Связи таблиц

- `offers.product_id` → `products.product_id` — предложение относится к товару.
- `offers.supplier_id` → `suppliers.supplier_id` — предложение принадлежит поставщику.
- `supplier_members.user_id` → `users.user_id` и `supplier_members.supplier_id` → `suppliers.supplier_id` — связь пользователей с организациями «многие ко многим».
- `product_buyers.product_id` → `products.product_id` — связь товара с его заказчиком.
- `product_buyers.user_id` → `users.user_id` — заказчик-физическое лицо.
- `product_buyers.supplier_id` → `suppliers.supplier_id` — заказчик-организация или ИП.

При подключении к базе в `db/database.py` включается проверка внешних ключей через `PRAGMA foreign_keys = ON`.

### Создание базы и импорт JSON

- `sql/schema.sql` — SQL-команды `CREATE TABLE` для создания шести таблиц.
- `db/database.py` — подключение к SQLite.
- `db/import_json.py` — перенос данных из JSON в таблицы SQLite с помощью `executemany()`, `commit()` и `rollback()`.
- `data/*.json` — исходные данные для переноса.

JSON-файлы `users.json`, `suppliers.json`, `products.json`, `offers.json`, `supplier_members.json` и `product_buyers.json` сохранены в каталоге `data/`.

Таблицы можно создать из корня проекта командой (при установленной утилите `sqlite3`):

```bash
sqlite3 data/trpf.sqlite < sql/schema.sql
```

### SQL-запросы

В файле **`sql/queries.sql`** содержатся 18 проверенных запросов:

| № | Назначение |
|---|---|
| 1 | Список всех товаров |
| 2 | Список всех поставщиков |
| 3 | Товар по ID вместе с заказчиком |
| 4 | Поставщик по ID |
| 5 | Предложения для конкретного товара |
| 6 | Предложения товара с сортировкой по цене |
| 7 | Предложения товара с сортировкой по сроку доставки |
| 8 | Общее количество предложений |
| 9 | Минимальная, максимальная и средняя цена предложений товара |
| 10 | Количество предложений для каждого товара (`GROUP BY`) |
| 11 | Количество предложений для каждого поставщика (`GROUP BY`) |
| 12 | Товары с более чем одним предложением (`HAVING`) |
| 13 | Предложения поставщика с товарами и заказчиками |
| 14 | Общий список предложений с товарами и поставщиками |
| 15 | Предложение по ID с товаром, поставщиком и заказчиком |
| 16 | Общее количество поставщиков |
| 17 | Общее количество пользователей |
| 18 | Общее количество товаров |

Используются `SELECT`, `WHERE`, `JOIN`, `LEFT JOIN`, `COUNT()`, `MIN()`, `MAX()`, `AVG()`, `GROUP BY` и `HAVING`.

В `sql/queries.sql` для проверки запросов приведены конкретные ID. В Django-представлениях значения из URL передаются параметризованно, через `?` и кортеж параметров. Для сортировки предложений используются только заранее разрешённые SQL-конструкции, выбираемые по GET-параметру `sort`.

### Использование SQL в Django

- В `products/views.py` из SQLite получаются товары, заказчики и связанные предложения; для товара рассчитывается статистика цен.
- В `suppliers/views.py` получаются поставщики и их предложения вместе с товарами и заказчиками.
- В `offers/views.py` получаются общий список предложений и подробности отдельного предложения.
- В `homepage/views.py` выполняются агрегатные запросы для страницы `/statistics/`: общие количества сущностей и количество предложений по каждому товару и поставщику.

База предметной области `data/trpf.sqlite` используется отдельно от служебной базы `db.sqlite3`, которую Django создаёт при применении собственных миграций. Переход на Django ORM планируется на следующих этапах.

## Хранение данных

На текущем этапе используются два способа работы с данными:

- **Консольная версия** работает с JSON через функции модуля `storage.py`.
- **Веб-версия Django** получает данные предметной области из SQLite (`data/trpf.sqlite`) посредством SQL-запросов.

JSON-файлы также используются как источник первоначального заполнения таблиц SQLite скриптом `db/import_json.py`.

## Установка зависимостей

Из корневого каталога проекта создайте виртуальное окружение:

```bash
python3 -m venv venv
```

Активируйте его (macOS/Linux):

```bash
source venv/bin/activate
```

Установите зависимости:

```bash
python3 -m pip install -r requirements.txt
```

## Запуск консольной версии

Из корневого каталога проекта выполните:

```bash
python3 main.py
```

Консольная версия предоставляет меню для работы с данными предметной области из JSON.

## Запуск веб-версии

Убедитесь, что в `data/trpf.sqlite` создана схема и импортированы данные из JSON.

Для служебных компонентов Django примените миграции:

```bash
python3 manage.py migrate
```

Проверьте конфигурацию и запустите сервер разработки:

```bash
python3 manage.py check
python3 manage.py runserver
```

Веб-интерфейс будет доступен по адресу: http://127.0.0.1:8000/

Для остановки сервера нажмите `Ctrl+C` в терминале.

## Тестирование

Проверка автоматизированных тестов:

```bash
python3 -m pytest -v
```

Проверка Django:

```bash
python3 manage.py check
```

Статический анализ типов:

```bash
python3 -m mypy --strict .
```

Проверка стиля Python-кода:

```bash
python3 -m flake8 . --extend-exclude=venv
```

Проверка целостности базы и внешних ключей (при установленной утилите SQLite CLI):

```bash
sqlite3 data/trpf.sqlite "PRAGMA integrity_check;"
sqlite3 data/trpf.sqlite "PRAGMA foreign_key_check;"
```

Первый запрос должен вернуть `ok`, второй — не вернуть строк с нарушениями.

Проверка выполнения запросов из `sql/queries.sql`:

```bash
sqlite3 -bail data/trpf.sqlite < sql/queries.sql > /dev/null && echo "SQL-запросы: OK"
```

Дополнительно в браузере проверяются страницы списков, подробностей, сортировка предложений, страница статистики и обработка несуществующих идентификаторов.
